## Purpose

Управление YAML-конфигурациями проектов: загрузка из директории, валидация структуры, предоставление данных о проектах (путь, сервисы, алиасы) другим компонентам системы.

## ADDED Requirements

### Requirement: Загрузка конфигов проектов при старте
Система SHALL при старте прочитать все `.yaml` файлы из директории, указанной в переменной окружения `PROJECTS_CONFIG_DIR` (по умолчанию `/configs`). Каждый файл описывает один проект.

#### Scenario: Успешная загрузка нескольких конфигов
- **WHEN** в директории `/configs` находятся файлы `alpha.yaml` и `beta.yaml`
- **THEN** система загружает оба проекта и делает их доступными для остальных компонентов

#### Scenario: Пустая директория конфигов
- **WHEN** директория `PROJECTS_CONFIG_DIR` не содержит `.yaml` файлов
- **THEN** система запускается без проектов, MCP-серверы не генерируются, демон не запускается

#### Scenario: Директория не существует
- **WHEN** директория `PROJECTS_CONFIG_DIR` не существует
- **THEN** система SHALL залогировать предупреждение и запуститься без проектов

### Requirement: Формат конфига проекта
Каждый YAML-файл SHALL содержать обязательное поле `name` (строка) и `path` (строка, путь к коду проекта). Опциональные поля: `aliases` (массив строк), `postgres`, `redis`, `nats`, `minio`, `docker` -- каждый описывает подключение к соответствующему сервису.

#### Scenario: Минимальный конфиг
- **WHEN** файл содержит только `name: alpha` и `path: /projects/alpha`
- **THEN** проект загружается без сервисов, только доступ к коду через filesystem

#### Scenario: Полный конфиг с алиасами
- **WHEN** файл содержит `name`, `path`, `aliases: [project-alpha, альфа]`, `postgres`, `redis`
- **THEN** проект загружается со всеми указанными сервисами и алиасами

#### Scenario: Невалидный конфиг без name
- **WHEN** YAML-файл не содержит поле `name`
- **THEN** система SHALL залогировать ошибку и пропустить этот файл, продолжив загрузку остальных

#### Scenario: Невалидный конфиг без path
- **WHEN** YAML-файл содержит `name`, но не содержит `path`
- **THEN** система SHALL залогировать ошибку и пропустить этот файл

### Requirement: Поддержка алиасов имён
Каждый проект MAY иметь поле `aliases` -- массив строк. Алиасы используются для распознавания проекта по упоминанию в тексте запроса. Алиасы регистронезависимы.

#### Scenario: Поиск проекта по алиасу
- **WHEN** проект имеет `name: alpha` и `aliases: [project-alpha, альфа, шара]`
- **THEN** упоминание любого из имён "alpha", "project-alpha", "альфа", "шара" (в любом регистре) идентифицирует этот проект

#### Scenario: Конфликт алиасов между проектами
- **WHEN** два проекта имеют пересекающиеся алиасы
- **THEN** система SHALL залогировать предупреждение и использовать первый загруженный проект для конфликтного алиаса

### Requirement: Формат подключений к сервисам
Каждый сервис (postgres, redis, nats, minio, docker) описывается объектом с полями, специфичными для типа сервиса. Для postgres: `host`, `port`, `user`, `password`, `database`. Для redis: `host`, `port`, `db`. Для nats: `url`. Для minio: `endpoint`, `port`, `access_key`, `secret_key`, `bucket`, `use_ssl`. Для docker: `host` (путь к сокету или TCP адрес).

#### Scenario: PostgreSQL подключение
- **WHEN** конфиг содержит `postgres: {host: 192.168.1.50, port: 5432, user: pguser, password: secret, database: alpha_db}`
- **THEN** система формирует connection string `postgresql://pguser:secret@192.168.1.50:5432/alpha_db`

#### Scenario: Docker через Unix socket
- **WHEN** конфиг содержит `docker: {host: unix:///var/run/docker.sock}`
- **THEN** система использует этот путь для подключения к Docker

### Requirement: Горячая перезагрузка конфигов
Система SHALL поддерживать перечитку конфигов без перезапуска. При изменении файлов в `PROJECTS_CONFIG_DIR` система перечитывает их и обновляет список проектов.

#### Scenario: Добавление нового проекта
- **WHEN** в директории конфигов появляется новый файл `gamma.yaml`
- **THEN** система обнаруживает его и добавляет проект `gamma` в список доступных

#### Scenario: Удаление проекта
- **WHEN** файл `alpha.yaml` удаляется из директории конфигов
- **THEN** система удаляет проект `alpha` из списка (новые запросы не будут его видеть)
