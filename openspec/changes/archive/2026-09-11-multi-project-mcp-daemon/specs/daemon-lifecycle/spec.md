## Purpose

Управление жизненным циклом персистентного демона `qodercli remote-control`: запуск при старте прокси, контроль здоровья, автоматический перезапуск при падении, корректное завершение при остановке прокси.

## ADDED Requirements

### Requirement: Запуск демона при старте
При наличии хотя бы одного загруженного проекта система SHALL запустить процесс `qodercli remote-control` с флагами: `--directory /projects` (корневая директория проектов), `--mcp-config <путь к сгенерированному MCP JSON>`, `--capacity 32`. Процесс запускается как дочерний процесс прокси.

#### Scenario: Успешный запуск демона
- **WHEN** загружены проекты и сгенерирован MCP JSON
- **THEN** система спавнит `qodercli remote-control` и ожидает создания Unix socket (`/tmp/qoder-{PID}.sock`)

#### Scenario: Запуск без проектов
- **WHEN** конфиги проектов отсутствуют
- **THEN** демон не запускается, прокси работает в режиме без MCP (только базовый qodercli)

### Requirement: Health check демона
Система SHALL периодически проверять здоровье демона. Если процесс демона завершился или socket недоступен, система SHALL автоматически перезапустить демон.

#### Scenario: Падение демона
- **WHEN** процесс демона завершается с ненулевым exit code
- **THEN** система SHALL залогировать ошибку и перезапустить демон в течение 5 секунд

#### Scenario: Потеря socket
- **WHEN** Unix socket демона перестаёт отвечать
- **THEN** система SHALL убить старый процесс (если жив) и перезапустить демон

### Requirement: Корректное завершение
При остановке прокси (SIGTERM, SIGINT) система SHALL отправить сигнал завершения демону и дождаться его остановки.

#### Scenario: Graceful shutdown
- **WHEN** прокси получает SIGTERM
- **THEN** система отправляет SIGTERM демону, ждёт завершения до 10 секунд, затем принудительно убивает (SIGKILL)

### Requirement: Перезапуск при обновлении MCP конфига
При изменении списка проектов (добавление/удаление/изменение конфига) система SHALL перезапустить демон с обновлённым MCP JSON.

#### Scenario: Добавлен новый проект
- **WHEN** в директории конфигов появился новый файл
- **THEN** система перегенерирует MCP JSON, перезапустит демон с новым `--mcp-config`

#### Scenario: Изменён конфиг существующего проекта
- **WHEN** файл `alpha.yaml` изменён (например, новый пароль PostgreSQL)
- **THEN** система перечитает конфиг, перегенерирует MCP JSON, перезапустит демон

### Requirement: Логирование состояния демона
Система SHALL логировать ключевые события жизни демона: запуск, готовность (socket создан), падение, перезапуск, остановка.

#### Scenario: Лог при запуске
- **WHEN** демон успешно запущен и socket создан
- **THEN** система логирует: PID демона, путь к socket, количество загруженных проектов
