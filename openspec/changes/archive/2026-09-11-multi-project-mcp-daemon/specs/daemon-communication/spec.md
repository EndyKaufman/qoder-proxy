## Purpose

Отправка пользовательских запросов к демону `qodercli remote-control` через Unix socket и получение ответов в формате stream-json для передачи клиенту.

## ADDED Requirements

### Requirement: Отправка запроса через Unix socket
При получении API-запроса (chat/completions или completions) система SHALL отправить промпт демону через Unix socket и получить ответ в формате stream-json.

#### Scenario: Успешная отправка и получение ответа
- **WHEN** пользователь отправляет POST /v1/chat/completions с промптом
- **THEN** система отправляет промпт демону через socket, получает stream-json ответ и передаёт его клиенту

#### Scenario: Демон недоступен
- **WHEN** socket демона недоступен (демон перезапущается)
- **THEN** система SHALL вернуть HTTP 503 с сообщением о недоступности сервиса

### Requirement: Поддержка streaming ответов
Система SHALL поддерживать передачу streaming-ответа (SSE) клиенту по мере получения чанков от демона.

#### Scenario: Streaming ответ
- **WHEN** клиент отправляет запрос с `stream: true`
- **THEN** система передаёт каждый чанк от демона клиенту через Server-Sent Events

#### Scenario: Non-streaming ответ
- **WHEN** клиент отправляет запрос без `stream` или с `stream: false`
- **THEN** система собирает полный ответ от демона и возвращает его одним JSON-объектом

### Requirement: Передача model в запросе к демону
Система SHALL передавать демону запрошенную модель (после маппинга через существующий каталог моделей) через соответствующий параметр.

#### Scenario: Модель из запроса
- **WHEN** клиент запрашивает `model: "gpt-4o"`
- **THEN** система маппит её в `auto` (по существующей логике) и передаёт демону

### Requirement: Таймаут запроса
Система SHALL ограничивать время ожидания ответа от демона значением `QODER_TIMEOUT_MS` (по умолчанию 120000 мс). При превышении -- отменять запрос и возвращать ошибку.

#### Scenario: Превышение таймаута
- **WHEN** демон не отвечает в течение `QODER_TIMEOUT_MS`
- **THEN** система отменяет запрос к демону и возвращает HTTP 504 Gateway Timeout
